# Margin

A local, selection-first writing playground for WebMCP. Built with React, TypeScript, Vite, and Tiptap/ProseMirror.

## Run

```sh
npm install
npm run dev
```

Open http://localhost:5183. The development server binds to your own computer. Documents and review notes are saved in this browser's local storage; there is no account, backend, or model API key.

## First experiment

1. Highlight a sentence in the sample document.
2. Expand **Developer tools** below the document and choose `propose_replacement`.
3. Click **Load example**, change the replacement text, then **Run tool**. For an explanation, choose `add_comment` and set `kind` to `explain`.
4. Accept or reject the suggestion beside the affected passage. Comments expand in place and can be resolved. Undo restores an accepted edit.
5. Repeat, but edit the original passage before accepting. The suggestion becomes stale and cannot overwrite your new text.

Manual responses are written by you; they are not generated by AI. The inspector calls the same application handlers as WebMCP, but does not simulate native browser tool discovery.

## Connect an API agent

Install our BYOA extension and configure an API provider in its Options. The connection picker lists every profile, even if there is only one. Reload the extension and then Margin at http://localhost:5183.

The top-right **Not connected** button opens a connection panel. Choose **Connect agent** to allow requests from Margin for this browser session. When connected, the button shows the connected profile’s name, with **Working…** during a task. The panel provides **View agent chat**, **Agent settings**, and **Disconnect**. Disconnect cancels ongoing work and blocks new requests until you reconnect. Connection state is separate from WebMCP tool registration, which remains visible in Developer tools.

Highlight a passage, choose an editing action, enter an instruction, and press **Send**. BYOA handles provider/API credentials and executes the page tools; proposals and comments appear inline for review. The sidebar stays closed unless you choose to view the chat. Use sample content while testing: your chosen provider receives the request and tool results.

The indicator confirms that an extension API profile is configured and connected; provider authentication is exercised when you send a request. Without the extension, the editor and manual Developer tools still work. There is no companion process, pairing token, relay port, or local-agent connection UI in this version.

The earlier local-agent/companion prototype is preserved on the local branch `archive/local-agent-2026-11-07` (snapshot `87c1ea3`).

### Tools

- `get_selection`: stable selection ID, selected text, nearby context, revision, requested action, and instructions.
- `get_document_outline`: headings only.
- `find_text`: case-insensitive exact matches, with short context (up to 50).
- `propose_replacement`: pending plain-text replacement for a selection; never applies it directly.
- `add_comment`: explanation or editorial comment attached to a selection.

Accept/reject are human UI actions. Tool arguments are validated. Tool calls and results appear in the inspector (in memory, up to 100 calls). Logs are not persisted.

## Implementation

`src/engine.ts` tracks selections using ProseMirror transaction mappings. Edits before a selection move its anchor; changes within its captured content make it stale. A captured fragment includes formatting, so formatting changes also invalidate proposals. Suggestions and their inline review controls are ProseMirror decorations rather than document content until accepted. Controls do not become part of exported text or the saved document tree. The in-app sidebar is removed; developer tools stay collapsed below the document, while the extension owns the agent interface. Comment and suggestion data is stored with the document.

`src/tools.ts` contains tool schemas, argument validation, shared execution/logging, and the native WebMCP adapter. `src/App.tsx` is the interface. The adapter is intentionally small because WebMCP is experimental.

Replacement text is inserted as text, never HTML. Newlines create paragraphs. Existing rich formatting within the replaced passage is not retained. This prototype supports one local document, not collaborative multi-user editing. Opening the app in multiple tabs can overwrite local storage; use one tab per draft. Undo applies to document edits; review history remains an audit of your decisions, and undo does not reopen accepted suggestions.

## Checks

```sh
npm test
npm run build
npm run dev       # separate terminal, before browser tests
npm run test:e2e
```

Browser tests use an installed Google Chrome with a fresh isolated profile. Unit tests exercise range tracking; browser tests cover selection, suggestions, acceptance/undo, persistence, stale edits, comments, inspector errors, and responsive rendering.

Margin now imports the experimental shared client from `../../byoa-extension/sdk`. Both demos live under `demos/` in the BYOA repository. Boardwalk uses the same client on localhost:5184; connections remain separate by origin. Reloading BYOA and the page is required after rebuilding extension code. See `../../byoa-extension/sdk/README.md` for the current contract and prototype limitations.

The app now calls `agentboard.connect()` without building a profile picker. BYOA opens its own window showing the requesting site and all profiles. Select a profile and approve there. Cancel or close preserves any existing connection. Profile lists are no longer exposed to app code.
