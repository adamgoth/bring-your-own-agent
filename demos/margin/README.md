# Margin

A hostable, local-first writing app for you and your own agent. Built with React, TypeScript, Vite, and Tiptap/ProseMirror.

## Run

```sh
npm install
npm run dev
```

Open http://localhost:5183. The development server binds to your own computer. Documents and review notes are saved in this browser's local storage; there is no account, backend, or model API key.

## Documents and Markdown

Create a draft with **New document**, rename it using **Document title**, and switch drafts in the document list. Writing and review notes autosave in browser local storage. The original single-document demo draft migrates automatically; its old storage entry is retained as a backup.

**Import Markdown** creates a new document without replacing the current draft. Files up to 2 MB are accepted. Headings, paragraphs, bold, italic, lists, quotes, links, and code are supported. Raw HTML is sanitized; images, tables, and unsupported formatting are not preserved. **Export Markdown** downloads the current writing as `.md`; pending suggestions, comments, and review history are not included.

There are no accounts, cloud sync, or server-side document storage. Documents belong to this browser and origin: switching domains, protocols, or ports does not move your drafts. Export important writing before clearing browser data or moving to a hosted URL. Storage failures stay visible and prevent switching away from unsaved writing. Agent tasks keep document switching disabled until they finish.

Use **Suggest title** beside the title to name a document from its contents. Your agent receives up to the first 12,000 characters and can only return a title for that request. **Undo** restores the previous title. Manual title or document edits made while it runs take priority.

Submit agent prompts with **⌘ Enter** on Mac or **Ctrl Enter** on Windows/Linux. Plain Enter adds a new line.

## Draft with your agent

In an empty document, describe what you want to write and choose **Draft with your agent**. The agent receives only the `propose_document` tool for this task. Its Markdown response appears in a separate preview; **Use draft** inserts it, **Dismiss** discards it, and **Try again** requests another version. You can also ignore the prompt and type normally.

Typing or changing the document after the request starts disables acceptance, even if you undo your edits. Changes saved by another tab also prevent acceptance. Pending previews are saved with the document, but stay out of Markdown exports. Accepted drafts can be undone. Cancelled or expired request IDs cannot add previews.

## Host as a static app

Keep this app in the BYOA repository so its shared SDK import resolves during the build. It deploys independently of the extension and Boardwalk.

Margin's build first compiles the shared SDK with Margin's installed TypeScript compiler. A clean checkout only needs Margin's dependencies; installing or building the extension is not required.

From the repository root:

```sh
npm ci --prefix demos/margin
npm run build --prefix demos/margin
npm run preview --prefix demos/margin
```

On your static host, use the **repository root** as the build root:

- Build command: `npm ci --prefix demos/margin && npm run build --prefix demos/margin`
- Publish directory: `demos/margin/dist`
- Node: 22.13 or newer
- No environment variables, API keys, backend, or SPA route rewrites required.

Serve the generated files over HTTPS. Relative asset URLs support hosting at the domain root or a subdirectory. The host only needs the built `dist` files at runtime. BYOA connections require a top-level HTTPS page (or HTTP loopback for local development); iframe previews cannot connect. Visitors install/configure BYOA themselves and approve the hosted origin. The writing app remains usable without the extension.

The connection panel links to repository installation instructions until a verified store listing is available. Your agent's provider receives the instructions and tool context you request. API keys stay in the extension. The stylesheet currently loads Google Fonts; documents are never sent to that service.

## First experiment

1. Highlight a sentence in the sample document.
2. Expand **Developer tools** below the document and choose `propose_replacement`.
3. Click **Load example**, change the replacement text, then **Run tool**. For an explanation, choose `add_comment` and set `kind` to `explain`.
4. Accept or reject the suggestion beside the affected passage. Comments expand in place and can be resolved. Undo restores an accepted edit.
5. Repeat, but edit the original passage before accepting. The suggestion becomes stale and cannot overwrite your new text.

Manual responses are written by you; they are not generated by AI. The inspector calls the same application handlers as WebMCP, but does not simulate native browser tool discovery.

## Connect an API agent

Install our BYOA extension and configure an API provider in its Options. The connection picker lists every profile, even if there is only one. Reload the extension and then Margin at http://localhost:5183.

The top-right **Connect your agent** button opens a connection panel. Choose **Connect agent** to allow requests from Margin for this browser session. When connected, the button shows the connected profile’s name, with **Working…** during a task. The panel provides **View agent chat**, **Agent settings**, and **Disconnect**. Disconnect cancels ongoing work and blocks new requests until you reconnect. Connection state is separate from WebMCP tool registration, which remains visible in Developer tools.

Highlight a passage and choose **Improve this**, **Comment**, or **Explain**. Improve this offers optional **Clearer**, **Shorter**, **More natural**, and **More professional** presets; choose one and optionally add your own direction, then press **Suggest edit**. Without a preset or instruction, the agent improves clarity and flow while preserving meaning and voice. Comment and Explain each have a simple optional instruction field. BYOA handles provider/API credentials and executes the page tools; proposals and comments appear inline for review. The sidebar stays closed unless you choose to view the chat. Use sample content while testing: your chosen provider receives the request and tool results.

The indicator confirms that an extension API profile is configured and connected; provider authentication is exercised when you send a request. Without the extension, the editor and manual Developer tools still work. There is no companion process, pairing token, relay port, or local-agent connection UI in this version.

### Tools

- `get_selection`: stable selection ID, selected text, nearby context, revision, requested action, and instructions.
- `get_document_outline`: headings only.
- `find_text`: case-insensitive exact matches, with short context (up to 50).
- `propose_replacement`: pending plain-text replacement for a selection; never applies it directly.
- `add_comment`: explanation or editorial comment attached to a selection.

Accept/reject are human UI actions. Tool arguments are validated. Tool calls and results appear in the inspector (in memory, up to 100 calls). Logs are not persisted.

## Implementation

`src/engine.ts` tracks selections using ProseMirror transaction mappings. Edits before a selection move its anchor; changes within its captured content make it stale. A captured fragment includes formatting, so formatting changes also invalidate proposals. Suggestions and their inline review controls are ProseMirror decorations rather than document content until accepted. Controls do not become part of exported Markdown or the saved document tree. The in-app sidebar is removed; developer tools stay collapsed below the document, while the extension owns the agent interface. Comment and suggestion data is stored with the document.

`src/tools.ts` contains tool schemas, argument validation, shared execution/logging, and the native WebMCP adapter. `src/App.tsx` is the interface. The adapter is intentionally small because WebMCP is experimental.

Replacement text is inserted as text, never HTML. Newlines create paragraphs. Existing rich formatting within the replaced passage is not retained. Each document has its own title, writing, selection anchors, and review notes. Switching documents resets editor undo history. A newer save from another tab blocks conflicting writes; export the open draft and reload to recover. This is not collaborative multi-user editing. Undo applies to document edits; review history remains an audit of your decisions, and undo does not reopen accepted suggestions.

## Checks

```sh
npm test
npm run build
npm run dev       # separate terminal, before browser tests
npm run test:e2e
```

Browser tests use an installed Google Chrome with a fresh isolated profile. Unit tests exercise range tracking; browser tests cover selection, suggestions, acceptance/undo, persistence, stale edits, comments, inspector errors, and responsive rendering.

Margin imports `@byoagent/browser`, resolving its locally built ESM and declarations through aliases. Run root `pnpm build` before starting a demo directly. Both demos live under `demos/` in the BYOA repository. Boardwalk uses the same client on localhost:5184; connections remain separate by origin. Reloading BYOA and the page is required after rebuilding extension code. See `../../byoa-extension/sdk/README.md` for the current contract and prototype limitations.

The app calls `agentboard.connect()` to open the extension-owned profile picker. BYOA opens its own window showing the requesting site and all profiles. Select a profile and approve there. Cancel or close preserves any existing connection. Profile lists are no longer exposed to app code.
